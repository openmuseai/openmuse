# OpenMuse 多端全球化整改范围与实施计划

日期：2026-10-30。状态：已进入实施，优先完成 Android/iOS 商店路径；首批代码和共享测试已落地，生产接入和最终制品验收分别登记。适用 Desktop（macOS、Windows、Linux）、Mobile（Android、iOS）、Web 客户端。

本轮整改以现有 Host 和首发必需的随包插件为主体，保留 Word、PDF、表格的产品层，继续完成 GenOffice PPTX 的跨端集成。其他外置插件暂不进入官方首发发布目录。现有市场、安装和源管理能力保留，不以限制官方发布目录为由扩大功能裁剪。

技术基础沿用 [国际化与动态配置平台设计](GLOBALIZATION-RUNTIME-CONFIG-PLATFORM.zh-CN.md) 和 [地区与动态参数实现说明](REGIONAL-APPS-RUNTIME-REMEDIATION.zh-CN.md)。涉及本轮整改范围、内核边界和实施顺序时，以本计划和用户最新确认的边界为准。发布结果记录到各渠道发布单，计划状态不代表制品或生产服务已验收。

2026-10-30 移动验收进展：两端真实账号、云工作区、美国 Linux grant/文件读取、GenOffice 0.8.0 编辑保存、独立账号永久删除均通过，正式签名候选 1.0.0 (5) 已构建。生产配置输入、官方线上目录及渠道分发验收仍未关闭，不代表 G00–G14 全部完成。详见 [移动验收记录](../../app/openmuse_mobile/release_materials/14-全球化移动验收-2026-10-30.zh-CN.md)。

## 一 已确定的产品边界

| 事项 | 本轮执行边界 |
| --- | --- |
| 开放地区 | 当前只开放中国和美国。国内发行固定中国区；海外原生发行先选择数据地区，现阶段仅美国可用；欧洲、亚太无可用服务配置 |
| 语言 | 中英文离线预置。额外语言、已有消息翻译修复和已实现行为的参数由配置平台动态下发 |
| 三端一致性 | 统一地区、配置和语言契约；各端按已经可用并通过验收的能力开放功能，不要求通过全球化补齐全部平台功能 |
| Word PDF 表格 | 保留产品层的菜单、命令定义、语言资源、能力描述、签名资源和 Host 适配接口；尚未 ready 的解析、排版、渲染、编辑、导出内核不纳入本次首发 |
| GenOffice PPTX | 已完成基础全球化，作为本轮允许发布的插件继续集成；其已有 PPTX 引擎与尚未 ready 的 Word/PDF/表格内核分别管理 |
| 插件市场 | 保留现有插件发现、已安装管理、安装和源管理能力，整改首发可达界面的文案与配置接入 |
| 官方插件发布 | 官方首发目录只发布确认的随包插件和 GenOffice；其他外置插件不上架、不进入首发推荐。不因此封禁用户既有第三方源、清空缓存或改变已有插件授权 |
| 远程更新 | 已有文案、语言数据、经过校验的配置和已实现功能开关可动态更新。新代码、新执行能力、权限扩展、内核、信任根变化按对应发行与平台流程交付 |
| 本次交付 | 已按用户授权进入代码整改、真机验收及 Android/iOS 候选构建；商店提交和生产发布另行记录，当前候选尚有阻断项 |

Word/PDF/表格产品层可以保留在源码和资源中；正式界面仅展示当前可用能力。缺少内核时，不注册可调用的打开、编辑、保存、导出能力，不让用户进入空编辑器。是否存在已经独立就绪的系统预览能力，要单独验收并准确命名，不能用它推导完整 Office 产品已就绪。

本计划中的 Web 指 [Muse-Client Web 客户端](../../app/openmuse_web)，Muse-WebSite 仅作为法律、支持、账户删除和地区入口的外部依赖联验，不扩展为官网整站改版。HarmonyOS 不在本轮三端实施范围内。

## 二 实施前装配与差距（基线）

### Desktop

入口为 [openmuse_host](../../app/openmuse_host/lib/main.dart) 和 [openmuse_linux](../../app/openmuse_linux/lib/main.dart)。macOS/Windows 与 Linux 使用不同 Host 实现，整改和验收要覆盖两条实现。

账号、云工作区、配对 Host 在启动代码中安装；[桌面默认插件组合](../../distribution/openmuse_builtin_plugins/lib/openmuse_builtin_plugins.dart) 还包含 DSH、CLI、Helix、插件市场、文件查看器和原生输入诊断。主 Host 另外有 Word/PDF/表格产品注册及 GenOffice 随包安装路径，Linux 的装配与之并不完全一致。

已具备地区引导、运行时配置、共享语言控制器和通用 MCP 展示上下文。仍需盘点插件可见文案、本地 DSH 展示层、系统菜单、安装与升级提示、文件关联、恢复标签及产品内核绑定。打包脚本已有的选择开关继续复用，对仍存在的必需内核检查逐项解耦，不能只隐藏 UI。

### Mobile

[移动端入口](../../app/openmuse_mobile/lib/main.dart) 直接装配认证、云工作区、移动配对、文件访问、定时任务、DSH Agent、语音和移动插件市场，没有使用桌面默认插件组合。

已具备首次地区选择、语言偏好和共享配置上下文。需要补齐启动 runtime 到 `OpenMuseMobileApplication` 的注入：当前启动调用没有传入 `runtime`，而原生插件配置适配器根据 `widget.runtime` 创建。还需核对 DSH 对话组件、配对错误、平台入口和市场页面的中文文案。

[随包资源声明](../../app/openmuse_mobile/pubspec.yaml) 已包含 Word/PDF/表格 MCPB，原生产品页面同时引用 `ioffice` UI 和内核相关依赖。需区分产品层资源与未就绪内核，解除首发包对后者的装配和构建要求。当前本地语音选择 `zh14m` 模型，翻译界面本身不能证明英文识别能力已就绪。

### Web

[Web 入口](../../app/openmuse_web/lib/main.dart) 使用共享认证、语言和配置能力。生产安装由 [Web 配置编译器](../../scripts/release/prepare-web-config.py) 固定到单个地区，加载时验证实际 origin 与挂载路径；不能把原生首次地区选择页面直接当作生产 Web 的地区切换实现。

Web 的 DSH 是 [同页挂载的原 Web 客户端](../../web/dsh-pane/src/main.js)，不是 Mobile 原生对话组件。当前 Dart 挂载接口传入容器与会话路径，需要补充语言数据和更新通道；DSH 加载失败等包装文案也需要迁移。语言切换不能依靠卸载、重建会话实现。

Web 已有语义路由、浏览器 locale 元数据和 Office 端口，但这不代表 GenOffice、产品层界面或文档能力已全部在浏览器验收。按现有浏览器能力做集成，不新增本次范围外的 Wasm 内核、远程执行平台或新的插件市场产品。

### 共享配置与语言基础

[配置 SDK](../../packages/openmuse_runtime_config)、[语言 SDK](../../packages/openmuse_i18n) 和 [配置后台](../../services/config-control) 已有签名发布、校验、缓存、语言资源按需下载及插件消息传递基础。本次扩展使用覆盖面，不重复建设另一套配置系统。

当前 [海外发行引导文件](../../packages/openmuse_runtime_config/assets/releases/overseas.json) 中配置发现地址、公钥及资源 origin 仍为空。正式生产输入可能通过发布环境提供，验收必须检查最终制品；采用这些默认值的包无法完成生产动态下发。

现有 [全球化静态门禁](../../scripts/ci/check_globalization.py) 主要检查地址和语言常量，并保留历史例外；未覆盖所有 UI 文案、签名产品 JSON 和仓库外界面。门禁通过不能作为翻译完整性或发布完成的证明。

## 四 跨端共用的整改规则

### 配置与地区

业务代码通过服务 ID、路由 ID、消息 ID、能力 ID 访问可变数据。发行引导文件维护受信配置入口、根公钥、允许的服务来源和离线默认快照；本地协议地址、稳定 URI 和类型常量按协议管理。

配置按产品、环境、发行渠道、数据区、平台及兼容版本管理，避免 Android/iOS/桌面/Web 共用不匹配的更新或展示策略。生产签名私钥只在发布侧，客户端和插件仅持有相应公开信任材料。

展示配置动态更新；账号和业务服务端点按会话绑定，变化时沿用已有暂存/重连机制，禁止把现有 token 随语言选择送往另一地区。服务域名、对象存储、日志及第三方模型接收方分别核查，不把界面选择的“美国”直接视作全链路数据驻留证明。

Web 的地区选择发生在区域站点定位与部署层：全球入口可选择并跳转已经部署的区域站点；区域应用保持固定地区的 origin、挂载路径和同源网关。查询参数、浏览器语言、URL 语言前缀只控制允许的展示意图，不改数据区。地区配置变更需与实际网关部署匹配。

### 语言与消息

统一使用 BCP 47 语言标识。语言包是消息数据，保留中英文离线回退，第三语言在签名目录、资源校验及渲染支持均满足后激活。失败时保留上一份有效展示状态；简体和繁体按目录与回退策略处理，不混用。

随包原生组件沿用共享 catalog，并按认证、配对、对话、市场、文件等模块登记消息所有权。独立 MCP 插件使用自身命名空间、消息契约和兼容哈希；宿主不导入插件业务实现。已有 ICU 与 GenOffice 的文本插值格式分别校验，不能通过全局字符串替换翻译界面。

宿主语言变更须到达 Flutter、原生系统入口、Host 自有 HTML、DSH 展示层和 MCP Apps。DSH/第三方展示层若没有现成语言接口，先确定并实现受控适配接口；禁止以改写用户消息、遍历替换第三方 DOM 或重启 DSH 代替接入。

翻译范围为产品展示文案和可本地化元数据。协议字段、错误码、命令 ID、资源身份、用户输入、历史对话、文稿、文件名和终端输出保持语义稳定。界面根据稳定错误码生成提示，原始错误信息不直接充当唯一用户反馈。

日期、时间、数字、大小单位及复数按格式 locale 展示。时区属于用户/业务语义，定时任务等保留其存储和执行含义。新增语言的 RTL、长文本、字体和 Material 原生支持独立验收，不仅检查文字是否替换成功。

### 动态开关与用户偏好

动态配置只驱动包内已实现的行为，读取时执行类型、范围及缺省校验。核心入口与对应操作都按所声明的配置语义处理，不能只改按钮显示。未 ready 的内核不能被远程开关声明成可用。

服务端运营默认不覆盖用户明确选择的语言、主题和工作台布局。配置与语言包不包含 token、私钥、文稿或模型密钥，产品开关不能授予资源访问权限或替代服务端权益。

市场继续保留现有能力。本计划不将 `plugins.market.enabled=false` 设为统一首发默认，也不增加“只允许官方插件执行”的统一限制；既有开关仍可按其已定义含义在相应部署中使用。

### Office 产品层与构建

Word/PDF/表格资源通过消息 ID 描述标签，保留命令和能力 ID，渲染时注入语言服务；已签名资源更新仍按资源契约和信任机制验证。原生菜单、对话框、占位提示和无障碍标签按实际发布能力接入。

逐端梳理“pub 依赖 → 原生注册 → 资源声明 → 构建检查 → 产品注册 → UI 入口”的依赖链。把未 ready 内核移出本次所需的依赖闭包，复用已有可选打包路径；资源层仍依赖内核类型时提取接口。单纯增加运行时条件不能保证 FFI、native assets 或平台注册已经移出包。

产品层测试使用定义、资源和能力端口验证，必要时用仅测试可用的适配器；生产界面不以 mock 内核宣称打开、渲染或保存成功。不要求本轮实现新的 Rust、FFI、Wasm 内核。

GenOffice 使用已经就绪的自身 PPTX 路径，其开关和消息契约继续独立校验。代码版本、签名、摘要和安装回执需在各端一致记录，旧 `com.openmuse.pptx` 阅读器与新插件的迁移和默认打开关系要明确。

## 五 执行顺序与阶段交付

主顺序为：**范围清单 → 共享契约和生产引导 → 共享必需插件与 Desktop 参考闭环 → Mobile 主路径 → Web 固定地区与 DSH 桥接 → 多端候选包验收**。Office 产品层和 GenOffice 在共享契约确定后即可开始，必须在最终集成验收前完成。

Desktop 先验证一条最小参考闭环，不要求等全部桌面平台发布通过后才开展 Mobile。Mobile 商店路径优先取得可提测产物；Web 和其他桌面平台按同一契约推进，接口变化须补全三端回归。

| 阶段 | 依赖 | 工作内容 | 交付物 | 完成条件 |
| --- | --- | --- | --- | --- |
| 阶段零 范围与依赖清单 | 本计划 | 按平台确认随包插件、实际可达入口、官方发布目录、Office 产品/内核依赖、可用 view/edit/export 能力；确认语音等可选功能是否首发启用 | 三端组成清单、能力矩阵、内核解耦清单、官方目录清单 | 每个公开入口有对应实现、责任模块和验收用例；未 ready 内核不会被纳入首发要求 |

## 七 各端完成条件

### 共用验收

1. 默认英文、显式中文、跟随系统语言、重启恢复、第三语言缺包下载和失败回退均可验证。翻译更新不清空用户状态，不恢复用户未选择的默认语言。
2. 参数/开关在已有应用实例中按声明生效；缺失、错误类型、越界、旧契约和旧客户端分别遵循已定义的兼容策略。
3. 配置签名、资源哈希、缓存与 sequence 回放保护通过；生产输入不含演示私钥或调试 endpoint。
4. 中国和美国的账号/配置缓存保持隔离；EU/APAC 不产生业务连接。私有账号/文稿数据、用户指定 Desktop、模型提供方和公共网站流量分别记录。
5. 官方目录与本次发布清单匹配；既有安装、卸载、启停、源管理和授权功能按原有能力回归。
6. Word/PDF/表格只有通过能力验收的入口可用；未 ready 内核不被编译、注册、加载或作为首发构建前置条件。包内资产与依赖闭包检查提供证据。
7. 文稿、用户输入、会话历史、文件身份和协议枚举未被翻译逻辑修改；在途任务、编辑状态与授权保持正确。

### Desktop 验收

macOS、Windows 和拟发布 Linux 产物分别检查启动引导、认证、工作区、配对服务、DSH、插件管理、文件查看、系统菜单、快捷键和原生对话框。默认终端/文本入口的菜单和错误跟随语言，PTY、子进程及已打开标签保持连续。MCP 文档切换语言不重建编辑器。

先完成可运行的参考平台闭环，再扩展其他 OS。某一 OS 的打包或平台适配未通过时，记录该端阻塞，不把其他端的成功作为其发布证据。

### Mobile 验收

Android/iOS 真机检查首次选择、冷启动/热启动、横竖屏、前后台、系统语言变化、文件选择与保存、离线/弱网、登录过期和账号删除。权限解释与首发实际功能一致；语音等可选功能按 G00 最终清单决定权限和模型验收，不在本计划中默认增加或删除权限。

Google Play 使用内测实际分发包，iOS 使用 TestFlight 候选核查签名、包内资源、原生库和功能。沿用 [移动发布执行单](../../app/openmuse_mobile/release_materials/09-国内海外上架流水线.zh-CN.md) 记录真实版本及审核事项，不把历史构建记录用作本次候选的验收。

### Web 验收

Chrome、Edge、Safari、Firefox 覆盖目标版本，检查固定地区 origin/挂载路径、`lang/dir`、语义路由、直接深链、刷新和登录回跳。确认浏览器偏好、配置缓存、静态资产和 DSH 模块的版本配套；多标签页在旧/新版本并存时遵守约定，不混用语言契约或认证上下文。

DSH 原客户端在同页挂载、语言更新、重连和卸载后正常工作，切换语言保持会话和草稿。插件、文件和 GenOffice 按浏览器已经实现的能力逐项验证；无法通过的能力不宣称三端对齐，也不为通过全球化验收临时引入未就绪内核。
