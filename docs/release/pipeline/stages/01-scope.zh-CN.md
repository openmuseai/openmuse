# 01-scope · 需求与首发范围

负责人：产品负责人。状态与证据单独保存在每次发布的 `stages/01-scope.json`。

## 输入与目标

明确版本、渠道、国家、设备与首发能力，生成独立发布单。当前案例是美国首发，Host 必需能力、OpenMuse Notes 与 Slides；不能直接扩写成全套 Office 功能。

前置节点：无。

## 执行步骤

- 写清用户故事、验收标准、支持格式、离线能力、Desktop 依赖与不支持项。
- 逐渠道分配构建号；Google Play versionCode 与 Apple build number 分别递增，不要求两者相同。
- 决定目标年龄群体、收费/订阅、销售地区、发布方式和服务区。内容分级与“面向儿童”分别判断。
- 记录 APP 备案号、主体、域名与包名。国内备案号仍占位时，国内正式提审保持阻断。
- 确认审核 Desktop、演示工作空间、支持邮箱及服务维护人。

## 输出与验收

发布单 `release.json`；范围/验收清单；各仓库与服务的变更范围。所有页面与商店文案只描述本期实际能力。

证据不足保持 partial/pending；通过后由负责人填写 passed、owner 和 evidence。后续修改使本节点结论失效时，重新打开相关节点。
