# 12-archive · 上线观察、复盘与归档

负责人：发布与运维负责人。状态与证据单独保存在每次发布的 `stages/12-archive.json`。

## 输入与目标

归档命令在任何阶段都可生成快照；本节点仅在实际上线和观察完成后关闭。

前置节点：11-publish。

## 执行步骤

- 观察崩溃/ANR、登录、文档保存重开、Desktop 联动、投诉/删除/举报处理和成本，按发布单约定窗口复盘。
- 对本次源代码、制品、政策、素材、审核和发布建立关联；源码未冻结或缺少历史证据时明确标识，不补造成功记录。
- 用 archive-inputs.json 显式列出文件并逐项复核；归档签名二进制、公开证书摘要，不归档私钥/P12/JKS、API/SMTP 密钥或审核密码。
- 执行 pipeline.py archive，再 verify-archive；归档包有完整 MANIFEST.json、逐文件 SHA-256 和整包 .sha256。
- 历史快照不覆盖，生成新文件名；本地 ZIP 作为公司内部材料，另复制至公司受控持久存储并验证恢复。仓库中的 dist/ 默认不进入 Git。
- 后续版本复制模板新建发布单，复用品牌与通用流程；商店规则、政策、账号可用性和截图尺寸重新核对。

## 输出与验收

受控归档、哈希清单、复制/恢复验证、观察报告、遗留事项和下一版本输入。本次已归档快照不代表审核通过或正式发布。

证据不足保持 partial/pending；通过后由负责人填写 passed、owner 和 evidence。后续修改使本节点结论失效时，重新打开相关节点。
