# 发布材料归档规范

每个发布单位于 `docs/release/runs/<id>/`，主文件 `release.json` 只索引产品版本、各 lane、制品和商店状态；阶段结论分别放在 `stages/<id>.json`。物料由 `archive-inputs.json` 按文件显式列举，禁止默认递归打包整个项目、家目录或 /tmp。

## 目录和内容

| 目录 | 内容 | 复用方式 |
| --- | --- | --- |
| run/ | 主发布单、12 个节点回执、归档输入清单 | 下一次用 new 生成空白单 |
| pipeline/ | 本次采用的流程、脚本及渠道说明快照 | 日常以仓库最新版本为准 |
| artifacts/ | 最终 AAB/IPA/APK、原有 release.json 与签名报告 | 更新版本必须重新构建 |
| materials/ | 图标、feature graphic、原始截图及 provenance | 核对视觉一致性和当日规格后复用 |
| demo/ | 图文指南、演示 PPTX、图片、资源来源 | 新功能同步更新指南和 VPS 演示区 |
| policies/ | 本次对外英文政策快照和抓取时间/URL | 下次逐条复核，不默认为永久有效 |
| evidence/ | 测试、配置/签名摘要、上传、处理、送审、失败与发布证据 | 只证明对应构建和观察时点 |
| MANIFEST.json | 所有归档条目的来源、类别、字节数、SHA-256 | verify-archive 逐项复核 |

## 白名单与私有材料

每项包含 `source`（仓库相对文件路径）、`target`（包内路径）、`category`、`sha256`、`reviewedForSecrets: true`。变更文件后必须重新复核及更新摘要；脚本拒绝摘要不符、重名、路径穿越、符号链接、常见私钥/API 密钥和敏感凭据文件名。

这不是通用秘密检测器。截图、二进制、嵌套 ZIP 和自由文本仍需人工确认；审核员密码、API/SMTP 密钥、SSH 私钥、P12/JKS/keystore、身份证和营业执照原件都不进入此材料包。备案公开证书/指纹可归档，私钥恢复资料仅保留公司密钥库引用。不要把 reviewer credentials 写进节点回执。

## 创建、校验和持久保存

archive 命令先核对最终制品及全部输入 SHA-256，再写包内实际字节摘要，完成后再次逐文件验证。输出 ZIP 和整包 `.sha256` 权限为仅当前用户读写；已有快照拒绝覆盖。验证 zip 内摘要可以发现损坏，传输/恢复时还要和公司另存的整包 `.sha256` 比对；摘要本身不是数字签名。

`dist/` 被 Git 忽略，本地归档完成后由发布负责人复制到公司的受控持久存储，并记录位置、访问范围、保留策略和一次恢复验证。本轮没有指定外部归档库，记录中应保持“本地已验证、外部副本待登记”。不要因为归档成功将审核、发布、监控或源码冻结缺项改为通过。

源码快照应在构建前固定所有参与仓库和工具链。本次构建时工作树为 dirty，保留原 `internal-test-only` 构建记录及后置目录清单；不据此宣称可以从一个干净 tag 重现首发二进制。
