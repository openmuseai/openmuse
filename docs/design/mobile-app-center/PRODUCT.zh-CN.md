# 四 Tab 与应用中心交互设计 · 已批准实施

2026-11-02。按前文 taste skill（`.agents/skills/design-taste-frontend-v1/SKILL.md`）设计。本文保留获批产品基线；实现进度、原生验收和产物见 [实施与验收记录](IMPLEMENTATION.zh-CN.md)。[打开交互稿](index.html)。原型数据均为演示，不读取账号、工作区或插件服务。

## 推荐方案

底部固定四项：**首页 Home / 任务 Tasks / 应用 Apps / 我的 Account**。合并后的应用中心沿用 Discover 的可横向滚动标题导航，顶部仅保留 **概览 Overview / 发现 Discover**。默认是概览，承接 Workbench 的组件与布局；My Plugins 迁移到 **Account → 我的插件 My Plugins**，不再占用应用中心顶部栏目。

| 层级 | 中文 / 英文 | 用户目的 |
| --- | --- | --- |
| 底部 Home | 首页 / Home | 找到、打开和引用资源 |
| 底部 Tasks | 任务 / Tasks | 继续或创建对话、执行任务 |
| 底部 Apps | 应用 / Apps | 使用应用组件，发现可安装的应用 |
| Apps 默认栏目 | 概览 / Overview | 使用已启用且能在本端运行的插件组件，整理个人布局 |
| Apps 第二栏目 | 发现 / Discover | 搜索、了解与获取更多应用 |
| 底部 Account | 我的 / Account | 账号、偏好、模型、插件管理等设置 |
| Account 子页面 | 我的插件 / My Plugins | 查看安装状态、更新、启用/停用和卸载 |

“概览”比“我的应用”更符合现有 Workbench 的组件集合；也避免让用户把可直接使用的入口与 My Plugins 安装清单混为一谈。“工作台”保留为内部能力/布局名称，不要求重命名 SDK 或插件 wire 协议。英文 Account 使用单数，与现有应用保持一致。

## 页面与交互

### 应用 → 概览

顶端大标题直接是「概览 / 发现」两栏，不再叠加一行 Apps 标题。右侧只有「整理」文字按钮；进入整理后用紧凑的「取消 / 完成」动作栏替代标题导航，避免窄屏挤压。组件使用清晰的分组间距和单一层级表面，不做入口海报或嵌套大卡片。

- 承接现有插件贡献的 Workbench 卡片、置顶、次序、尺寸及宽度设置，保留既有账号与 scope 的布局。非移动端能力不出现在可用入口里；无 UI 的模型/后台工具只出现在管理页。
- 普通点击卡片进入插件应用页面；卡片内部的具体操作优先执行自身动作。整理模式中卡片内部操作暂停，提供独立的排序、显示/隐藏和适用的尺寸菜单；支持拖动，也提供向上/向下的无障碍替代动作。
- 「从发现添加」切到同一应用中心的 Discover，不 push 第二个应用中心。概览没有通用的“+ 新建资源”按钮；资源创建仍由 Home 与插件自身提供。
- 空白时说明「把要用的应用放在这里」，主操作「去发现应用」；若已有可用但被隐藏的组件，先提供「选择要显示的应用」。无插件能力时不展示假卡片。
- 本机组件不依赖 PC 在线。远程组件单独显示设备状态，离线时保留布局与说明，仅关闭需要远程连接的动作，不把整个概览变成错误页。页面中的设备信息是组件执行范围说明，不修改 Tasks 的设备/Workspace 选择。

### 应用 → 发现

保留当前 Discover 的内容框架：搜索、一个编辑推荐区域、纵向应用列表和详情。去除旧「My Plugins」顶部栏，不恢复 Featured / Office / UI / Coding 横向分类带、Store provider 或 Desktop plugins 区块。

- 搜索只针对发现目录，概览不共用这个搜索词。安装状态来源于同一 registry/store，列表与详情同步显示「获取 / 安装中 / 打开 / 不支持此设备」。
- 应用详情是独立二级页面，保留发布者、平台支持、能力/权限和安装状态。失败显示具体可恢复提示；安装完成后主按钮变为「打开」，不自动离开详情、不自动启动、不自动开启云端同步或后台服务。
- 可用组件按现有插件贡献与默认可见规则接入概览，不凭商店名称硬编码。安装结果提供可选动作「在概览中查看」，可将新组件滚动到可见位置并短暂强调；不重排用户原有布局。
- 目录加载失败保持当前搜索词与列表位置；缓存内容可继续浏览，只有依赖在线目录的操作受限。市场被地区/发行开关关闭时，概览仍可用，Discover 显示服务不可用说明。

### 我的 → 我的插件

放在 Account 的「应用与服务」组中，排在模型管理附近，与已有 Store provider 同组但仍是两个独立入口。Account 主页面不直接展示插件清单、更新按钮或删除操作。

- My Plugins 子页面使用返回导航，底部四 Tab 隐藏，与其他 Account 二级页面一致。顶部是页面标题和范围说明「此设备」，不暗示安装已跨端同步。
- 清单按实际插件状态展示，搜索并提供「全部 / 更新 / 已停用」筛选；无可靠更新来源时不显示虚构更新数或“全部更新”。原型更新状态只表示设计分支，不代表已实现的更新服务。
- 点击条目进入已安装详情；可以打开（有本端运行入口时）、停用/启用，以及能力允许时更新或卸载。内置不可移除插件不提供卸载；远程 PC 插件不混进本机安装清单。
- 停用仅移除运行入口，保留用户布局引用与数据，重新启用恢复原位置。卸载需要说明数据与关联功能影响并确认；卸载不等同删除用户文档或账号。
- 从管理页「发现更多应用」进入 Apps → Discover。系统 Back 及 iOS 返回手势返回原管理页及筛选位置，底部仍选中 Account；这是有来源的跨 Tab 导航，不留下两个相同市场页面。

## 导航状态规则

| 动作 | 预期 |
| --- | --- |
| 冷启动后首次进入 Apps | Overview，初次默认页面 |
| 会话内离开 Apps 再回来 | 保留上次栏目，各栏搜索与滚动位置独立保存 |
| 再点已选中的底部 Apps | 回 Overview；已经在 Overview 时滚到顶部 |
| 顶部栏目点击 | 同级替换内容，保持底部 Apps 选中，不新增返回栈 |
| 横向滑动 | 标题栏可横向滚动；首版不做内容区整页左右手势，避免干扰组件横滑、拖动与 iOS 返回 |
| 编辑中切栏目/底部/返回 | 有改动时提供保存、放弃、继续编辑；无改动直接退出，不静默丢失 |
| 详情返回 | 回到来源列表、原栏目、原查询、原滚动位置 |
| 账号切换 | 清理该账号临时页面状态，按新账号恢复布局；不串用另一账号插件和缓存 |

“默认概览”推荐解释为首次进入/冷启动默认，并提供重复点击 Apps 返回概览；不是每次离开都清空 Discover 的浏览位置。该规则已按用户批准采用。

## 视觉与可访问性

延续 OpenMuse 现有中性底色与单一蓝色强调：浅色背景 `#F6F7F9`、正文 `#20252D`、主蓝 `#3867C8`；深色背景 `#191C21`、表面 `#242830`、正文 `#EDF0F5`、主蓝 `#8FAFF5`。系统无衬线字体与 SF / Android 字体回退，既有产品字体优先。插件品牌图标不被强制染成主色。

标题栏选中 27sp/650、未选中 24sp/500；普通文字 15–17sp，状态文字不小于 12sp。标题保持单行，在标准字号下允许小幅收缩至 24/21sp，更多栏目超出时水平滚动；开启大字时保留用户字号并滚动，不强制缩小系统无障碍字号。点击区最小 44pt（Android 48dp），所有选中状态除颜色外有字重和下划线，VoiceOver/TalkBack 读出选中与排序动作。

四个底部图标统一为 24px 线性图标：Home 房屋、Tasks 对话框、Apps 四格、Account 人像；统一 1.7px 线宽，以主色与短横线标识选中，不混用某一个实心图标。首版仅用 160–220ms 的淡入与按压反馈，无持续漂浮或营销动效；尊重减少动态效果。卡片圆角 18–20pt、设置组 20pt，主要依靠底色/分隔与留白，不叠加多层阴影。

## 与框架的对应及实施范围

| 当前入口/接口 | 拟调整 |
| --- | --- |
| `WbTab.workbench` + `WbTab.discover` | 一个 `WbTab.apps`，内部 `AppsSection.overview/discover`；迁移旧保存的 tab/深链，不依赖 enum 下标 |
| `MobileWorkbenchPage` | 抽离可嵌入内容与整理动作，由应用中心统一管理标题与栏目；不嵌套两套 Scaffold/主标题 |
| `MarketDiscoverView` / `buildMarketPage` | 复用内容与安装行为，外层 Apps 持有顶部栏目；支持单独打开已安装清单，不用 mine 布尔值控制整个复合页面 |
| `MobileMyPage.onPlugins` | 接入真实 My Plugins 二级路由，复用 registry/store 和既有 provider 设置入口 |
| Workbench contributor / registry lifecycle | 原有能力、平台适配、布局持久化规则保留；不新增 Mobile 专属资源协议 |
| 旧 Workbench / Discover / My Plugins 深链 | 分别重定向到 Apps/Overview、Apps/Discover、Account/My Plugins，并正确保留来源返回路径 |

建议分三步：先抽离共享页面与路由、完成旧状态迁移；再落四 Tab 与 Overview/Discover 交互；最后迁移 My Plugins 并跑跨入口及回归。本文没有批准新增后台更新服务、修改插件安装安全策略或开发新的应用能力。

## 验收基线（实际结果见实施记录）

1. 底部恰好四项；冷启动、重复点击 Apps、跨 Tab 返回符合状态表。
2. 两个顶栏单行、可滚动；320/390/430pt、中英、大字和深浅色不挤压，不与整理按钮重叠。
3. 组件运行、内部滚动、编辑取消/保存/失败重试、布局按账号与 scope 隔离。
4. 安装详情 → 打开/概览；停用/启用同步改变概览，刷新 Discover 状态；无本端入口和无新版本不出现假按钮。
5. My Plugins 仅在 Account 中承担管理；源列表/查询/滚动与系统返回路径正确；卸载和用户文档删除边界清楚。
6. PC 离线、目录失败、市场开关关闭、未登录时，本机可用能力仍可操作。
7. Home 的资源打开/复制/新建、Tasks 的草稿及真实 PC 会话不因合并被重置。
8. iOS 与 Android 实机分别验收；本次原型审核不替代真机验收，Android 仍按用户先前要求暂停设备操作。

## 人工审核重点

- 底部「应用 / Apps」、默认栏「概览 / Overview」的命名是否采用。
- 默认栏只在首次进入/冷启动默认，还是每次切入 Apps 都回概览；推荐前者。
- My Plugins 的管理归属及从 Account 跨到 Discover 后的返回行为。

交互稿呈现结构、视觉和关键状态。排序采用向上/下操作作示意；尺寸菜单、真实权限与卸载确认细节按本文实现，原型不模拟真实插件执行或安装。
