# 多端资源引用、可用性与对话交接

**状态：P0 共享实现已落地，2026-11-02 完成 Android / iOS / macOS 原生 Flutter UI 验收。** 原始设计日期：2026-11-01。具体 API、限制与证据见 [实现契约](design/mobile-resource-center/IMPLEMENTED-CONTRACT.zh-CN.md) 和 [验收报告](design/mobile-resource-center/ACCEPTANCE-2026-11-02.zh-CN.md)。本稿不替代或修改 Accepted 的 Resource v1 wire；Cloud 仍为扩展目标。

## 1. 边界：共享框架与各端产品

统一资源身份、版本、Provider 权限/读写、插件打开/创建/编辑贡献、资源路由、对话引用交接、可用性与保留策略，属于**多端共享框架**。Mobile Home 只是其中一个入口。Desktop 资源浏览器、聊天卡片、插件面板也应消费同一套语义。

原生 UI、系统文件授权、平台剪贴板载体、网络传输与本机文件系统适配，属于各端 adapter。共享契约不表示各端都支持同样的运行时、文件大小或编辑模式；能力必须按目标端、安装状态、probe 和权限计算。

仓库已有基础：

- [Workspace / Resource Authority v1](WORKSPACE-RESOURCE-AUTHORITY-V1.zh-CN.md) 明确 Mobile、Cloud Sync、Sandbox、Office、Desktop 共享 Authority；Ref 与临时 Handle 分离。
- [客户端能力 profile](../packages/muse_resource_bridge/lib/src/profile.dart) 有 Desktop/Web/Mobile 差异；当前共享 Mobile profile 只声明 view，不能把新设计直接当成已支持通用移动编辑。
- [Engine Adapter manifest](../packages/muse_resource_contract/lib/src/engine_session.dart) 区分 platforms、placements、formats、modes、materializations。
- [DataPlaneBroker](../packages/muse_resource_bridge/lib/src/data_plane.dart) 检查 audience、generation、expiry、origin；当前远程数据面仅接受 read。

通用 creator、跨插件资源剪贴板、全局最近、版本保留与反向手机 Provider 的新增接口应放在共享契约/核心层，各端接 adapter；不在 `openmuse_mobile` 私建另一套资源协议。

## 2. 三个位置、三种寿命

| 角色 | 示例 | 意义 |
| --- | --- | --- |
| 资源源端 Source | 手机上的本地文档 Provider | 原件身份、内容版本与写入权威 |
| 执行端 Execution | PC 上运行的 DSH/Agent | 按授权读取某一版本，可能需要本地临时文件 |
| 展示/打开端 Presentation | 当前点击聊天卡片的 PC 或手机 | 选择本端可用插件，申请自己的访问会话 |

执行端与展示端即使同在一台 PC，也不是同一个授权 audience。Agent 的 grant 不能直接给 Desktop 编辑器使用。资源来源也不能用“当前选中的任务 Workspace”推断。

```text
稳定引用：作用域 + Source/Workspace/Mount/ResourceRef
内容版本：Revision + digest
对话绑定：发送时选中的版本 + 原件关联 + 明确保留策略 + 可选持久快照引用
读取会话：针对当前 consumer 重新签发的临时 Handle/lease
临时文件：执行 adapter 为某次任务生成的本机投影，可删除、可重建
```

稳定引用的存在不保证内容一直在线。版本被固定也不保证该版本的字节一直保留。临时文件被清理不等于原件消失；源文件还存在也不代表源 Provider 保留了对话所用的旧版本。

跨端消息、最近、剪贴板和长期存储不得把 `/tmp/...`、手机私有 path、Android content URI、配对 cookie 或短期下载 URL 当稳定资源地址。执行进程确实需要路径时，由私有执行 adapter 按租约生成，并只在当次工具上下文使用。

## 3. 手机引用文档到 PC 对话的链路

以手机源资源 R、发送时内容版本 V1/摘要 D1 为例：

1. 手机通过 Local Provider 取得稳定身份，确认系统文件授权及可用版本；用户选择引用，并明确授权提供给这个 PC 任务。
2. 对话消息绑定 R/V1/D1 与保留策略。源端授权按会话、作用域、操作和 TTL 签发；不能转发手机 UI 的现成 grant。
3. PC runtime 真正需要内容时，请求 V1。Source/Replica Resolver 找到合法来源，校验完整内容、版本与 digest 后，执行 adapter 在任务私有目录生成临时文件。没有验证完成不能报告附件读取成功。
4. Agent 消费该临时投影；对话保存的是资源/版本绑定和状态，不是这个目录路径。运行时生成的临时文件引用若进入聊天，Host 应转换为已登记的资源或明确的临时产物，不能包装成可永久点击的链接。
5. 临时目录清理后，在任何端点击卡片都重新 resolve 和 materialize；不尝试长期打开旧的 `/tmp/...`。本端插件收到的是新会话。

**P0 已通过共享 ResourceOriginBridge 补齐反向读取。** 手机仅对当前配对 PC 显式共享的资源响应前台轮询，PC 请求并验证确切版本。手机没有额外开启 HTTP 文件服务器；PC → 手机也使用同一 RPC/Provider 语义。旧 MobileWorkspaceMirrorClient 本身的能力没有被扩大宣称。

## 4. 点击到底打开原件还是对话版本

建议按入口明确区分：

- **Home/普通原件引用：** 默认请求原件当前版本，呈现来源与当前可用性。
- **已发送的聊天附件卡片：** 默认请求“这次对话实际使用的版本 V1”，保证前后内容一致；可另提供“查看原件当前版本”。不能悄悄用 V2 替换 V1。
- **复制聊天附件：** 复制 pinned 对话版本的引用；需要复制原件时使用明确的“复制原件引用”，不偷偷改变版本语义。

如果源文件已改为 V2，而 V1 的内容既没有保留快照、也无法从源端历史恢复，就显示“对话版本已不可用”，可另开当前版本。名称相同、digest 不同的文件不能当作当时的附件。

### PC 点击时的可用性矩阵

下表中的“有效副本”必须是 R/V1/D1 对应的已校验缓存/副本或显式保留的对话快照，且本次打开仍被策略授权。仅有元数据、相似文件名或无来源校验的临时残留不算。

| 手机 Source 可达且对当前 consumer 授权 | 其他有效副本可用 | PC 点击聊天卡片 |
| --- | --- | --- |
| 是 | 是 | 可优先使用本地合法副本，重新创建会话；打开 V1，标明对话版本/副本来源 |
| 是 | 否 | 向手机请求准确 V1，校验后重新生成本机投影；若手机已不保留 V1，不能假装成功 |
| 否 | 是 | 在副本自身保留与访问政策允许时打开 V1；标明原件离线，默认只读，不能显示已保存回手机 |
| 否 | 否 | 保留卡片名称、来源、版本信息，提示“来源离线，当前没有可用副本”；提供重连/重试或明确重新关联，不调用插件去打开废弃临时路径 |

“手机没有连接当前 PC”不一定等于源端离线：若已有被授权的其他通道可达，可以通过该通道获取；若仅在别处在线但未授权当前 consumer，仍不能读取。账号相同也不是隐式授权。共享 Resolver 不自动绕过配对边界。

手机屏幕亮着、有心跳、连着网络，也不证明 Local Provider 可以供数据。iOS/Android 进程暂停、系统授权撤销或 App 未运行，都可能使内容暂时不可达；以真实 Provider 请求与能力探测为准。

## 5. 临时缓存与持久对话快照：需要明确的产品选择

两种保留模式均应可表达，但**默认策略尚待审核**：

| 模式 | 承诺 | 不承诺 |
| --- | --- | --- |
| 仅引用原件 / 按需读取 | 不长期托管额外内容；在线且版本可恢复时可重读 | 手机离线、旧版本丢失、临时目录清理后仍必定可打开 |
| 随对话保留所用版本 | 经用户/工作区政策明确授权，在指定执行端或区域的附件存储中保留 V1；独立于任务临时目录 | 永久保留、自动上传 Cloud、跨区域任意复制、绕过副本自身权限 |

建议：需要“历史对话在手机离线后仍可打开附件”的产品应提供后者，并在发送时明确保留位置、保留周期/删除归属及不可用条件。不要把悄悄保留 PC 临时文件当作该承诺，也不要只保存 Revision 就声称有附件归档。用户未允许保留时使用前者并清楚提示可用性限制。

持久对话快照可以建为 Conversation Attachment Provider 内的新资源 S1，记录 provenance 指向原件 R/V1/D1；原件与对话副本是两个有明确关系的对象。受控可驱逐缓存也可以作为同版本的可用 replica，但不是对话的持久保留承诺。两者不混为一谈。

保留成功需要存储与元数据 receipt；绑定消息、持久快照与任务提交之间采用可幂等恢复的状态，不能消息说“已保留”而字节仍未提交。缓存被 GC、快照过期或删除后，重新计算可用性，不继续显示“离线可用”。

没有预先授予有效离线访问权时，源端离线应拒绝读取。若允许离线快照访问，需要有明确 TTL/撤销模型：完全离线时无法保证即时得知远端撤销，不能同时承诺“无限离线使用”和“远端撤销即时生效”。

## 6. 打开、新建、编辑：位置不同，契约一致

本次打开的有效能力，是 **资源/目标 Provider 的操作能力与权限、内容可达性、当前端的 handler/runtime/probe、请求模式与政策** 的交集；既不是文件扩展名，也不是手机是否装过某个插件。

- PC 点击手机资源：在 PC 的可用插件中选择；手机装的编辑器不会自动变成 PC 可运行的插件。
- PC 编辑手机原件：必须有源端写能力、重新授权、working copy 与源端 CAS commit/receipt；当前只读跨端数据面不足以完成。源端离线时，只能按显式产品能力保存本地草稿/新副本；不能报告已写回手机。
- 手机恢复连接后：可以显式尝试提交等待的草稿，但需检查 base revision/冲突、权限、幂等；不能按旧路径覆盖源文件。
- 编辑持久对话快照：默认只读；“另存并编辑”创建新资源并保留来源关系，不改写历史对话使用的 V1。
- 新建：creator 为共享插件贡献，目标 Provider 为被选中的保存位置；创建和呈现/执行端可不同，但每个组合都要声明并探测支持。不能因运行在 PC 就默认把新文件建到 PC，或因入口在手机就强制保存到手机。

普通“复制资源路径”仍是可读逻辑位置；可执行的统一引用必须承载上述身份/版本/意图。两者不能靠字符串长得像路径就互换。

## 7. 需要补齐的共享接口与现状差距

| 能力 | 当前基础 | 需要新增/协商的语义 |
| --- | --- | --- |
| 源注册/解析 | WorkspaceRef/MountRef/ResourceRef 与 provider 抽象 | 跨设备稳定 source 身份、手机反向 Provider、当前 reachability；不能以连接 ID 当持久源标识 |
| 指定版本读取 | 当前 materialize 将签发当时版本固定到 Handle | **现有 materialize(resourceRef) 不接受目标 revision**；不等于旧 Handle 过期后仍能取任意旧版本，需要明确的按版本解析/读取及不支持错误 |
| 副本选择 | 数据面检查来源与 grant | 经校验的版本/摘要、来源与可用副本目录、受控复制、当前授权、GC/过期状态；不做跨账号原始 digest 共享 |
| 对话资源绑定 | 通用 MCP/Agent content block 基础 | origin locator + pinned revision/digest + retention policy + 可选 snapshot resource；不能只存临时文件路径 |
| 临时投影 | materialization/lease/working copy 原语 | 会话/工具的按需 hydrate、私有临时路径、清理后可重新投影、用户取消和幂等 |
| 创建/改名/远程编辑 | 已有资源 draft/CAS 与只读远程读取基础 | 新资源分配、metadata mutation、远程写提交、权限/冲突 receipt；按 Provider/平台逐一验收 |

这些是待评审扩展，放入共享包/版本化 wire 与端适配，不私自在冻结 Resource v1 或 manifest v2 中增加未协商字段。旧端不支持时应明确能力不可用，不把不可达/无权限混成“不支持格式”。

建议将 availability 拆为可组合的状态，而非一个 online 布尔值：源端可达性、目标版本可恢复性、本次 consumer 权限、可用副本与保留状态、当前端 handler 可用性。相同资源可能“原件离线但可看对话快照”，也可能“源在线但目标旧版本不可恢复”。

## 8. 最小跨端验收集

手机 → PC 与 PC → 手机都验证：

1. 临时目录清空后，稳定引用不变，能按合法来源重新获取。
2. 源在线/离线 × 有效副本有/无，四格行为符合矩阵。
3. 原件改为 V2，对话 V1 不能静默变成 V2；不支持历史读取时明确报错。
4. 仅元数据缓存不能冒充离线可用；损坏/过期/不同 digest 的字节不能打开。
5. consumer 从 Agent 换成 Desktop 编辑器，必须重新授权；相同账号、不同 Workspace 也检查。
6. 手机在别处在线但未授权当前 PC、进程后台暂停、系统文件授权撤销，分别正确处理。
7. 只读快照不能写回原件；离线编辑不显示原件已保存；重连 CAS 冲突不覆盖。
8. 会话删除、快照保留期届满、缓存回收、设备移除及权限撤销有一致的引用/内容状态；不自动破坏源文件。

审核后再确定默认保留模式、保存位置/期限、共享接口版本和各端实施顺序。本稿不代表手机反向传输或离线快照已经实现。
