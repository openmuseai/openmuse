# S19 — 交互回环（输入 → 重排 / 重绘）

## 1. 职责

组成闭环：编辑/视图变化 → 重新驱动 S07 排版（MVP 全量）；滚动/缩放只重绘（S18 视口）；点击/选中经 S13 定位。说明「一条流水线如何被再次驱动」。

管线位置：**闭环收尾**（上游 S07–S18 全部可被触发）。

## 2. 核心实现（Java 参考）

```java
// Java：编辑事件 → FlowLayout.update → 增量重排边界
doc.addDocumentListener(event -> {
    FlowLayout.update(event);        // 把变更 cp 区间标记为 dirty
    coreThread.requestLayout(range); // 增量重排（MVP：全量）
});
// 视图变化（滚动/缩放）→ 只重绘，不重排
```

## 3. 数据模型

| 模型 | 语义 |
|------|------|
| 用户事件 | 滚动 / 点击 / 缩放 / 编辑（cp 变更） |
| dirty 区间 | 需要重排的 cp 范围（MVP 全量） |
| 重绘范围 | 视口可见页（S18） |

## 4. 输入 / 输出

| 项 | 内容 |
|----|------|
| **I** | 用户事件（滚动/点击/缩放/编辑） |
| **O** | 新 Snapshot（S12）或新指令集（S14）→ 重绘 |

## 5. 上下游

- **上游触发**：所有环节（编辑→S07；滚动/缩放→S18；点击→S13）。
- **下游**：重排→S12→S14→S15→S16 或 纯重绘→S18。

## 6. 边界 / 失败语义 / 不变量

- MVP **同步全量**重排；增量延后（wr-05 `03_relayout_cache` 占位）。
- 滚动/缩放只走 S18，不重新排版（否则性能爆炸）。
- 编辑必须走「本次编辑 → 文档变化 → 重新排版」，不能只重绘。

## 7. Rust 承接与现状

MVP 同步全量；wr-05 `03_relayout_cache` 占位（增量延后）—— **✗ 占位**。
