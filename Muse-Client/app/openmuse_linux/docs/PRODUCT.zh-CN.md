# OpenMuse Linux 产品方案

状态：首版工程实现与构建验收阶段。定位：面向 Linux 开发者的本地 AI 工作台，打开现有项目就能编辑、运行命令、与 DSH 协作。延续桌面产品的操作方式和数据契约。

## 使用人群与首要任务

第一优先是使用 Ubuntu、Debian 的开发者和技术创作者。用户已有本地目录，希望让 AI 在明确授权的工作区内读写文件，同时保留编辑器、终端和可审查的修改轨迹。账号用于云工作区与设备协作，本地匿名使用应能离线进入工作台。

首个完整流程：启动应用 → 打开或添加项目目录 → 左侧浏览文件 → 中间 Helix 编辑并保存 → 右侧选择模型、发送任务 → 查看结果并跳转到对应文件 → 关闭后重新打开项目。

## 窗口与交互

沿用三区布局：左侧项目树、搜索、插件与回收站；中间编辑器、多标签、预览和终端；右侧 DSH 对话、会话与模型配置。默认窗口 1440×900，桌面环境提供标题栏、拖拽与窗口按钮；比例和面板布局由现有布局存储恢复。

Linux 使用 Ctrl 系列快捷键和标准剪贴板，不使用 macOS 专用窗口控件。对话中的文件打开与工作区切换经过 Host Broker；DSH 的本地端口改变时重建 WebView，不保留过期页面。Host 弹出模态窗口时隐藏原生 WebView，关闭后恢复，避免覆盖权限或设置对话框。

## 首版范围

| 能力 | 交付内容 | 验收要点 |
|---|---|---|
| 本地工作区 | 目录、文件操作、搜索、回收站、布局恢复 | 重启后目录与布局恢复，文件保存到原位置 |
| 编辑与终端 | 仓库内 Helix fork、PTY、公共文件预览 | UTF-8、中文输入、Ctrl+C/V、缩放、保存、终端退出 |
| AI 工作流 | 固定 DSH 版本、Node 随包、WebKitGTK 原生嵌入 | 无系统 Node 也能启动，token 换取 cookie，流式响应与停止 |
| 账号与设备 | 公共 GoTrue、云工作区、配对组件 | 匿名使用、登录/登出、密钥环保存、设备状态 |
| 插件 | 公共插件 SDK、市场与 MCP App 适配 | 不将 macOS 原生二进制当作 Linux 插件安装 |
| 安装升级 | deb、便携 tar.gz、校验和、来源记录 | 干净系统安装、升级保留用户数据、卸载不误删项目 |

原生 Office 编辑、应用内升级安装、托盘、全局快捷键、自动启动和 Flatpak/Snap/AppImage 不作为首版完成条件。Word/PDF/表格专用原生编辑器必须先完成各组件的 Linux 动态库、许可证和样本验收，才能加入默认组合。公共 Markdown/图片等预览保持可用。

## 发行策略

先交付 Debian 12 / Ubuntu 24.04 的原生 arm64 和 amd64 构建通道；每个已发布架构都必须有自己的真实构建和启动记录。本机是 Apple Silicon，因此容器默认产出 arm64；amd64 通过原生 CI 构建，未跑完前不能宣称已交付。

X11 与 Wayland 分别验收。Xvfb 中的启动成功只证明 X11 虚拟显示可运行，不能替代 GNOME/KDE、输入法、缩放和 GPU 的实机检查。Ubuntu 22.04、其他发行版及发行格式后续按实际用户需求扩展。

## 发布门槛

1. 静态分析、工作台回归测试和 DSH 运行时认证测试通过。
2. 可执行文件、Helix、Node 为目标架构 ELF，系统依赖可解析，包内没有逃出安装目录的符号链接。
3. 安装后无开发工具链也能打开本地工作区；对话、文件跳转、保存、终端和重启恢复有记录。
4. 密钥环可用与不可用时均有明确行为，不把凭据写入日志或普通配置。
5. 完成 Linux 桌面的中文输入、剪贴板、多屏缩放、对话框遮挡、关闭后子进程清理与卸载验收。
6. 发布包附许可证、依赖来源、版本、架构和 SHA256；正式对外发行前补齐依赖清单及必要声明。
