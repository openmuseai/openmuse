# 移动端域名与联网审计底稿

检查日期：2026-10-28。以下是对 `app/openmuse_mobile/lib`、移动插件和共享 Dart 包生产源码的**静态代码检查**，尚不是最终联网抓包清单。渠道包的动态配置、用户选择的 Desktop/插件服务和后端跳转可能引入其他域名；正式备案及隐私申报以实际发布包的网络日志、域名权属和服务用途复核。

| 域名/地址 | 代码中的用途 | 处理 |
| --- | --- | --- |
| `openmuseai.com` | 默认 GoTrue 认证、Cloud Workspace 服务；隐私、条款、支持与账户删除页面 | 已备案网站域名；核对 APP 备案记录中服务域名填写及实际 API 路由 |
| `beian.miit.gov.cn` | “我的”页 APP 备案编号的外部查询链接 | 政府备案查询系统，不作为自有服务域名申报 |
| `plugins.openmuseai.com` | 默认 MCP 插件市场/Registry 源 | 核对权属、解析、后端服务、是否在备案及隐私材料中列明 |
| 动态 `*.plugins.openmuse.io` | 插件市场按摘要拼接远程 MCP App 页面及参数 URL | 功能和域名归属需核查；逐商店评估可下载/远程执行内容，抓包确认实际访问。不能仅凭静态字符串认定已备案 |
| 用户配置的 Registry URL、已配对 Desktop 地址 | 由本地配置或用户操作指定的网络目的地 | 需在功能说明及隐私材料中解释，真机抓包检查 URL 校验与授权边界 |
| `127.0.0.1` / `localhost` | 本地开发或设备内回环 | 不属于互联网服务域名；确认正式包没有把开发地址误作默认服务 |

`surface.openmuse.invalid` 是共享代码的虚拟来源，`cloud.openmuse.ai` 出现在认证界面的本地化**示例**，不应直接填为实际生产服务域名。发布配置若传入 `OPENMUSE_MOBILE_MARKET_URL`、`OPENMUSE_MCP_REGISTRY_URL` 等，必须把解析后的真实主机加入本表和每次发布记录。

## 正式封版方法

1. 对国内 APK、Google Play AAB 经内测分发的实际 APK、iOS IPA、鸿蒙正式包分别记录构建时所有 `dart-define`、资源配置及远程配置。禁止把口令写入发布记录。
2. 在新装、登录、文档查看/编辑、同步、语音、插件市场、账户删除等路径抓取 DNS 与 HTTPS 目标主机；区分自有服务、第三方 SDK、用户选择的设备及外部链接。
3. 对每个实际主机保存权属证明、数据类别、接收方、地区、隐私政策对应条款和备案填报口径；与国内各渠道及 Apple/Google 隐私表单逐项核对。
4. 新增域名、SDK 或远程插件能力时重新审计，确认不会让备案域名或商店声明与实际包不一致。
