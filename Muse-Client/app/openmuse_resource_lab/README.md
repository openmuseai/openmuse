# Resource framework acceptance Host

Development-only macOS runner for the same resource UI, native adapters, plugin registry, paired gateway and real DSH protocol used by the applications. It never replaces the production application and refuses release mode. The account, workspace and pairing token are disposable fixtures. Model credentials stay in the private DSH process and are never compiled into this app.

Start `scripts/release/start-resource-acceptance-dsh.py` with private model-input/state paths, then run this app with `OPENMUSE_RESOURCE_QA_INPUT` pointing at the resulting private runtime file. Mobile UI acceptance connects to this Host. Use a trusted test network and terminate the lab and its owned DSH process afterward. This lab is not evidence of a production GoTrue login or a store-signed artifact.

The repeatable PC UI target is `integration_test/resource_reference_pc_test.dart`. Build it with `flutter build macos --debug --target integration_test/resource_reference_pc_test.dart`, then launch the built executable with `OPENMUSE_RESOURCE_QA_INPUT` and `OPENMUSE_RESOURCE_QA_EVIDENCE` set to private input and evidence directories. Run one phone at a time with a unique `run` and `pcReviewGate: true`. The PC target waits for the phone's real conversation, removes execution projections, clicks both references online, releases the phone to finish, then tests both references after the actual bridge becomes unavailable. It writes `result.json`, screenshots and `proof.json`; macOS has no integration_test native result plugin, so the explicit result file is authoritative. The target closes its clients, gateway and source services before completing.

Mobile's target is `app/openmuse_mobile/integration_test/resource_center_acceptance_test.dart`. Private input contains `origin`, `controlPort`, `account`, disposable `accessToken`, `pairingCode`, `run` and `pcReviewGate`; no model key belongs in that input. Android must use the isolated `.acceptance` application ID and `scripts/release/run-android-acceptance.py`. For a USB connection, reverse only the two lab ports. iOS uses an authorized private-network origin (including numeric ULA IPv6), a development-signed AOT test app and an app-container input file. This does not permit production cleartext origins.

The separate browser check is `scripts/release/check-resource-desktop-web.mjs --runtime PRIVATE_RUNTIME --evidence EVIDENCE_DIRECTORY`. It uses the real DSH journal and production reference presentation script in its own headless Chrome profile; it never attaches to a user's browser. It checks presentation and the Host message, not OS-native WKWebView/WebView2 interaction. Full scope, commands and final evidence are linked from `docs/design/mobile-resource-center/ACCEPTANCE-2026-11-02.zh-CN.md`.

Supplemental native macOS mouse-driven acceptance is recorded under `target/mobile-acceptance/2026-11-02/resource-center/wkwebview-ui/`: open Desktop web, select the persisted conversation, click its retained and origin-only references while the phone bridge is offline, then return to the conversation. These are actual WKWebView interactions; the separate headless result remains scoped to browser presentation.
